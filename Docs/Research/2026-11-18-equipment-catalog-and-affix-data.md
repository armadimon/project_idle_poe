## 관찰에서 얻은 자체 기획 해석

GGG는 무기 기반을 피해·속도·치명타 같은 여러 축으로 보여 주며, 방어구에는 방어 방식에 따른 차이를 둔다. PoEDB는 장비 분류별 옵션을 찾아볼 수 있게 한다. 이 자료를 바탕으로 기반 역할을 드러내고 장비 성급과 분리하는 방식을 제안한다. 첫 장비 10칸·무기 3계열·계열당 기반 3종·고정 특성 1개와 모든 성급에서 역할을 유지하는 규칙은 우리 게임을 위한 제안이다.

PoE의 모든 장비 분류·혼합 방어구·특수 옵션을 처음부터 재현하는 대안은 조합 폭이 넓지만 데이터·전투·공략 의존 관계도 늘어난다. 부위 자체를 크게 줄이는 대안은 관리량이 적지만 제작 목표를 나눌 공간이 작아진다. 실제 장비 칸은 유지하면서 첫 계열과 역할을 제한하는 안을 권한다.

공략이 작동 조건·전환 조건·다음 교체를 설명한다는 해석은 기존 [커뮤니티 사례 연구](PoE1/Community-Cases.md)에서 가져온다. 이번에 커뮤니티의 새 관측값·드롭률·현재 빌드 성능을 추가 검증한 것은 아니다.

## 호환성·적용·검증

현재 프로젝트는 Unity 6000.3.11f1의 C# 프로토타입이다. 공식 웹 문서·PoEDB와 Lua 기반 PoB를 직접 실행 패키지로 도입하지 않는다. 분류 구조·후보/등급/수치의 분리·장비 교체 비교라는 접근을 자체 문서 설계에 참고하고, 장착 데이터와 계산 기능의 구체적인 구현은 별도 조사·제안 뒤 진행한다.

| 구분 | 이번 결과 |
| --- | --- |
| 자료 조사 | 공식 아이템·무기·방어구 페이지와 PoEDB 분류/한손검 페이지 열람 |
| 코드·라이선스 | 기존 고정 PoB 조사와 MIT 링크를 재사용. 새로운 라이브러리 도입 없음 |
| 적용 | 승인된 드롭 기획과 다음 미승인 장비 편성·기반 구조 제안 작성 |
| 실제 실행 | PoE·PoB·Unity에서 장비·공식·분포를 실행 검증하지 않음 |

승인 후 장착 조합·계열별 후보 공유와 성급별 기반 후보를 검토하고, 옵션·전투 수치표를 확인한 뒤 6개 옵션 생성 가능성, 한손/양손의 차이, 기반별 유효 선택과 제작 출발점의 획득 시간을 검증한다. 이번 단계에는 밸런스 수치를 외부에서 복제하거나 게임 데이터를 구현하지 않는다.
