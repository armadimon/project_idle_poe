# 게임 기획 체계 도입 조사

2026년 11월 13일 확인한 외부 원고의 작업 방법을 바탕으로, 사용자 확인을 중심에 둔 작은 기획 체계를 구성한다. 원본을 실행형 프레임워크처럼 설치하는 대신 결정 기록과 기획 단계, 문서 규격과 검증 절차를 자체 작성하는 방식을 권장한다.

## 원고에서 확인한 작업 원리

- 2부: 문서의 상태와 계층을 명시하고 작은 결정 단위로 연결한다.
- 3부: 데이터를 늘리기 전에 필드와 의미를 합의한다.
- 10부: 문서·데이터 형식의 정확성과 결정의 타당성을 따로 확인한다.
- 18부: 결정의 이유, 사용자 확인과 영향 범위를 기록한다.
- 19부: 새 결정이 초기 방향과 맞는지 검토한다.
- 부록 K: 작업 절차는 특정 실행 도구와 분리해 적용할 수 있다.

각 장의 로컬 링크와 저작자표시는 [참고자료 안내](../../References/README.md)에 모았다. 이 목록은 조사 결과이며, 원고에 등장하는 사례의 성과나 모든 도구를 이 프로젝트에서 재현했다는 뜻은 아니다.

## 대안 비교와 권장안

| 방식 | 장점 | 부담과 제약 |
| --- | --- | --- |
| 통합 기획서 하나 | 시작과 전체 열람이 쉽다 | 결정 이유와 변경 영향이 섞이고 세부 항목별 확인 이력이 흐려진다 |
| 원고의 운영 체계 전면 이식 | 대규모 문서·운영 업무까지 다룰 수 있다 | 현재 프로젝트에 없는 업무까지 생기며 원고에 소개된 도구가 모두 제공되는 것도 아니다 |
| 작은 기획 체계 자체 작성 | 사용자 확인, 버전 관리와 변경 추적을 바로 적용할 수 있다 | 이후 문서가 늘면 검색과 자동화 범위를 확장해야 한다 |

세 번째 방식을 권장하고 적용한다. 현재는 장르·조작·플랫폼 세 결정만 확인됐으므로 이 규모에 맞게 출발할 수 있다. 권장 방식과 적용 범위, 검증 계획은 파일 작성 전에 사용자에게 제안했다.

## 적용 범위

원본을 커밋 고정 서브모듈로 보관하고 출처 기록을 둔다. 기획 문서는 방향, 결정, 질문 순서와 템플릿으로 구성한다. 모든 세부 기획은 사용자 확인 뒤 결정으로 기록한다. 결정 문서의 메타데이터는 `키: JSON 값` 형식으로 제한하여 표준 라이브러리만으로 검사한다.

원문 표현이나 원고의 예제 코드를 복사하지 않고 문서와 도구를 자체 작성한다. 외부 원고에 적용되는 조건과 표현의 이용 범위는 [원본 LICENSE](../../References/game-design-ai-practice/LICENSE), [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/), [Creative Commons FAQ](https://creativecommons.org/faq/#what-do-the-terms-and-conditions-of-a-cc-license-apply-to)에서 확인했다.
