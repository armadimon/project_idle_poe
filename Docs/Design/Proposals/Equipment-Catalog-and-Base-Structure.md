# 장비 편성·기반 구조 묶음 제안

상태: 아래 내용은 아직 승인되지 않았다. [장비 득템·파밍 대상](../Systems/Equipment-Drops-and-Farming-Targets.md)에서 정한 목표 부위·성급 드롭에 실제 장비 분류를 연결하는 첫 데이터 구성안이다.

## 이번 추천 묶음

| 항목 | 제안 |
| --- | --- |
| 장비 칸 | 주무기·보조 장비·머리·갑옷·장갑·장화·허리띠·목걸이·반지 2칸, 총 10칸 |
| 첫 무기 계열 | 한손검·양손도끼·마법봉 3종부터 구성 |
| 보조 장비 | 한손검·마법봉에는 방패 장착 가능. 양손도끼는 양손을 사용해 보조 장비와 동시 장착 불가 |
| 무기 기반 | 한손검·양손도끼는 피해형·속도형·치명형, 마법봉은 주문 피해형·시전 속도형·치명형의 계열당 3종 |
| 방어구 기반 | 머리·갑옷·장갑·장화·방패에 방어도형·회피형·보호막형 3종씩 |
| 장신구 기반 | 목걸이는 힘·민첩·지능형, 반지는 화염·냉기·번개 저항형, 허리띠는 생명력·방어도·보호막형 각 3종 |
| 고정 특성 | 기반마다 역할을 나타내는 고정 특성 1개. 수치는 같은 기반·성급에서 고정, 기본 4종 제작 작업으로 변경하지 않음 |
| 성급과 기반 | 모든 기반 역할을 1~5성에 제공. 성급은 제작 잠재력, 기반은 빌드에서의 역할로 구분 |
| 옵션 후보 공유 | 같은 무기 계열끼리, 같은 방어구 부위끼리, 같은 장신구 종류끼리 추가 옵션 종류 후보 공유. 반지 두 칸은 같은 후보 사용 |

기반 표기는 기획용 역할 이름이다. 최종 아이템 고유명·외형은 별도다. 묶음 전체를 승인하거나 수정할 행을 지정할 수 있다.

## 편성과 파밍의 연결

반지 2칸은 같은 종류의 장비를 각각 장착하는 칸이다. 두 반지가 서로 다르게 제작될 수 있으며 반지 파밍은 한 종류로 선택한다. 같은 종류의 일반 희귀 기반을 두 칸에 장착하지 못하게 하는 제한은 제안하지 않는다. 고유 장비의 장착 제한은 별도다.

보조 장비의 첫 목록은 방패다. 쌍수·무기 교체 세트·화살통과 추가 무기 계열은 이번 첫 구성에 넣지 않는 안이다. 이는 해당 요소를 영구 배제하는 결정이 아니라 먼저 제작·파밍 관계를 검토할 목록이다. 양손과 한손+방패의 추가 옵션 총량 차이는 이후 기본 성능·옵션 수치와 전투 검증에서 함께 다룬다.

승인된 목표 부위 파밍에서는 주무기·보조 장비·머리·갑옷·장갑·장화·허리띠·목걸이·반지를 고르게 하는 안이다. 무기 부위를 고른 경우 해당 성급의 세 계열·각 세 기반이 모두 유효 후보가 되며, 기존 승인대로 기반 9종 사이를 균등 추첨한다. 무기 계열이나 기반을 추가로 지정하는 새 통제 기능은 이번에 추가하지 않는다. 다른 부위는 각 3개 기반을 균등 추첨한다.

보조 장비를 쓰지 않는 양손 구성이라도 방패 파밍 선택 자체를 막지 않아 다른 빌드의 장비를 준비할 수 있게 한다. 특정 현재 빌드에 맞는 옵션만 자동으로 나오는 드롭 보정은 제안하지 않는다.

## 기반·옵션의 역할 구분

무기의 기본 성능은 해당 무기를 쓰는 공격이나 주문의 출발 성능, 방어구 기본 성능은 방어 방식의 출발 성능으로 정의할 계획이다. 세부 전투 계산은 아직 확정하지 않는다. 고정 특성은 추가 옵션 6칸과 별개인 1개이며 기반을 고르는 이유를 보여 주는 역할이다.

같은 부위의 방어도형·회피형·보호막형은 같은 추가 옵션 종류 후보를 공유한다. 기반의 방어 방식만으로 계열을 다시 쪼개 숨은 옵션 풀을 만드는 방식은 피하려는 안이다. 무기는 한손검·양손도끼·마법봉을 각각 계열로, 장신구는 목걸이·반지·허리띠를 각각 계열로 구분한다.

다음 **계열별 옵션·전투 적용·7등급 수치표** 묶음에서는 이 목록을 기준으로 접두·접미 후보와 각 효과의 적용 대상을 함께 제안한다. 장비 자체만 바꾸는 수치와 캐릭터 전체에 적용하는 수치를 문구에서 명확히 구분하고, 각 기반의 고정 특성 효과·수치와 기본 성능도 같은 표에서 제시한다. 힘·민첩·지능의 실제 효과, 공격·주문·회복·방어 계산과 스킬 조건을 정하지 않은 채 숫자만 정식 밸런스로 채우지 않는다.

이번에 확인하는 것은 장착 목록·기반 역할·특성 개수/고정 방식과 후보 공유 범위다. 개별 추가 옵션 목록·수치, 방어 계산, 무기별 스킬 호환성·요구 능력치·젬 슬롯·성장 비용·해금 시점은 후속 묶음으로 구분한다. 기존 프로토타입 무기·근력 조건·젬 연결의 구현 승인은 그대로 해당 범위에서 다룬다.

## 대안과 권장 이유

대안은 주무기·갑옷·장갑·장화·장신구처럼 5칸으로 줄이고 각 부위의 기반을 하나씩만 두는 방식이다. 장비 관리량은 줄지만 같은 부위에서 제작 출발점을 비교하고 여러 장비에 역할을 나눠 담는 폭도 좁아진다.

추천은 **10칸과 소수 계열·역할이 명확한 기반**이다. 장비별 옵션 조합을 만드는 공간을 남기면서 첫 목록을 제한해 파밍과 제작을 비교하려는 안이다. 실제 재미·빌드 다양성·완성 시간은 아직 검증하지 않았다.

## 조사·적용·검증 범위

[장비 분류와 데이터 조사](../../Research/2026-11-18-equipment-catalog-and-affix-data.md)에 GGG 공식 자료·PoEDB·기존 PoB 조사 버전, 라이선스와 호환성·재사용 제약을 정리했다. 이번 분류·개수·고정 규칙은 우리 게임의 자체 제안이며 PoE의 현재 목록을 그대로 채택한 것이 아니다.

승인 후 한손검+방패·양손도끼·마법봉+방패 사례의 장착 관계, 반지 공유 후보, 모든 성급에서의 기반 후보 수, 기본·추가 드롭의 부위 보존과 균등 확률, 계열별 후보 공유를 먼저 검토한다. 옵션·전투 수치표를 확인한 뒤 추가 옵션 6개를 유효하게 채울 수 있는지, 한손/양손 간 총 옵션과 생존·피해의 차이, 기반별 선택 이유와 제작 출발점의 획득 시간을 비교한다.

이 제안으로 Unity 데이터·장착·전투 기능을 구현하지 않았다. 구현할 때 현재 프로젝트 구조와 공식 기술 문서를 조사하고 적용·검증 계획을 먼저 제안한다.
