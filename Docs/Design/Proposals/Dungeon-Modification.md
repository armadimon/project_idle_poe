# 던전 변화의 잠금 토글과 교체 대상 제안

## 확인된 방향

사용자는 **재화를 소모해 던전에 패널티를 추가하고 보상을 높이는 시스템**을 기획에 포함하도록 요청했다. PoE의 맵 모딩을 참고하는 도입 방향은 [DEC-0060](../Decisions/DEC-0060-currency-funded-dungeon-penalties-and-better-rewards.md)에 기록했다. [무료 재도전 입장](../Decisions/DEC-0059-no-separate-entry-cost-for-competition-retries.md)은 별도 원칙으로 유지한다.

던전 변화는 [DEC-0061](../Decisions/DEC-0061-dungeon-modification-for-farming-only.md)에 따라 **파밍에만 적용**한다. **최고 도달 단계 경쟁은 이 변화를 적용하지 않고 공통 도전 조건을 유지**한다. 패널티는 [DEC-0062](../Decisions/DEC-0062-randomly-assign-farming-dungeon-penalties.md)에 따라 플레이어가 고르지 않고 무작위로 부여한다. 재추첨은 [DEC-0064](../Decisions/DEC-0064-reroll-one-selected-dungeon-penalty.md)에 따라 바꿀 패널티 하나를 지정해 무작위로 교체하고 나머지는 보존한다. [DEC-0065](../Decisions/DEC-0065-right-side-lock-checkbox-for-dungeon-penalty-rows.md)에 따라 각 줄 우측에 잠금 체크박스 토글을 둔다. 잠금 해제와 교체 대상의 연동 방식, 패널티 종류·개수·수치·확률과 삭제 허용 여부, 비용·횟수·새 결과 적용 및 보상과 지속 범위는 아직 정하지 않았다.

## 조사에서 참고한 부분

GGG의 개발 회고에서 비용·위험·보상을 연결한 설계 의도를, PoEDB에서 던전 변화와 보상 관련 표현을, 커뮤니티·poe.re에서 빌드별 맵 옵션 대응과 필터·설정 공유 사례를 확인했다. 구체적인 출처·확인 버전·라이선스·Unity 호환성과 실제 실행 미검증 범위는 [맵 모딩 조사](../../Research/2026-11-17-dungeon-modification.md)에 둔다.

우리 게임에 적용할 패널티와 경제 규칙은 자체 설계한다. PoE의 통화·지도 아이템·옵션 개수·아틀라스·실패 제한이나 오픈소스 데이터는 가져오지 않는다.

## 확인된 적용 범위

던전 변화는 **파밍에 적용하고 경쟁 기록에는 적용하지 않는다.** 사용자는 최고 단계 경쟁에도 적용하는 대안과 비교해 이 1안을 선택했다. 파밍에서 얻은 장비·재료를 제작과 빌드 개선에 활용하고, 최고 단계 경쟁은 공통 도전 조건에서 성과를 비교한다. 확인 근거는 [DEC-0061](../Decisions/DEC-0061-dungeon-modification-for-farming-only.md)에 기록했다.

이번 결정은 적용 범위까지다. 별도 던전·모드·입장 화면의 구성, 경쟁의 구체적인 공통 조건·기록 인정·동률 처리는 아직 정하지 않았다. 장비·스킬이나 그 밖의 캐릭터 능력치를 통일하는 승인도 아니다.

## 확인된 패널티 부여 방식

**패널티는 플레이어가 고르지 않고 무작위로 부여**한다. 사용자는 무작위 후보 중 선택·무작위 부여·직접 지정의 세 대안 중 2안 무작위 부여를 선택했다. 확인 근거는 [DEC-0062](../Decisions/DEC-0062-randomly-assign-farming-dungeon-penalties.md)에 기록했다.

이번 결정은 부여 방식까지다. 재추첨 범위와 잠금 토글 방향은 아래와 같이 확인했다. 패널티의 종류·수치·개수·중첩과 추첨 확률, 삭제·취소와 추가 통제 수단의 허용 여부, 재화 소모 시점과 비용·보상 수치는 별도 확인한다. 무작위 부여를 선택했다는 이유로 모든 패널티를 같은 확률로 뽑거나 전투마다 자동으로 새로 뽑는 규칙을 확정하지 않는다.

## 확인된 패널티 교체 범위

**바꿀 패널티 하나를 지정해 무작위로 교체하고 나머지는 보존**한다. 사용자는 전체 무작위 재추첨·한 개를 지정해 무작위 교체·재추첨 없음 중 2안을 선택했다. 확인 근거는 [DEC-0064](../Decisions/DEC-0064-reroll-one-selected-dungeon-penalty.md)에 기록했다.

이번 선택은 한 개 교체와 나머지 보존까지다. 교체 결과의 즉시 적용 또는 기존 결과와 선택, 추첨 확률·같은 패널티 재등장·중복, 비용·횟수·실행 조건·보상 변경은 별도로 확인한다.

## 확인된 잠금 토글의 조작 방향

사용자가 제안한 대로 **각 패널티 줄 우측에 잠금 버튼을 체크박스 토글로 배치**한다. 체크한 줄은 보존할 패널티를 표시한다. 확인 근거는 [DEC-0065](../Decisions/DEC-0065-right-side-lock-checkbox-for-dungeon-penalty-rows.md)에 기록했다.

| 표시 | 의미 |
| --- | --- |
| 잠금 체크 | 해당 줄을 보존 대상으로 표시 |
| 잠금 해제 | 해당 줄을 교체 대상에 포함할 수 있음. 실제 교체 대상과의 연동 방식은 다음 확인 |

한 번에 잠금 해제할 수 있는 줄 수와 교체 대상 선택의 연동 방식, 기본 체크 상태·전체 잠금 시 처리·잠금 유지 기간·잠금에 따른 비용 변화는 미정이다. 우측 토글 배치만으로 미잠금 줄을 모두 함께 재추첨하는 규칙을 채택하지 않는다.

이번 확인은 조작 기획까지다. 화면 전체 시안, 토글 크기·터치 영역·색·아이콘·상태 연출과 실제 UI 리소스·엔진 구현은 아직 수행하지 않았다.

## 다음 확인인 잠금 해제와 교체 대상의 연동 방식

아래 두 안은 아직 승인되지 않은 제안이다. 현재 확인된 한 개 교체 규칙을 유지하는 방식과, 여러 미잠금 줄을 함께 바꾸도록 범위를 넓히는 방식을 비교한다.

| 대안 | 잠금 해제와 교체의 관계 | 장점과 검토할 부담 |
| --- | --- | --- |
| 1안: 교체할 한 줄만 잠금 해제 — 추천 | 한 줄만 잠금 해제할 수 있고 그 줄을 무작위 교체. 다른 줄을 해제하면 기존 줄은 자동 잠금 | 선택한 2안의 한 개 교체를 유지하며 대상이 명확함. 여러 줄을 바꾸려면 한 줄씩 진행해야 함 |
| 2안: 여러 줄 해제 후 모두 교체 | 여러 줄을 잠금 해제할 수 있고, 실행하면 해제한 줄을 함께 무작위 교체 | 바꿀 여러 줄을 한 번에 지정할 수 있음. 현재 한 개 교체 규칙의 범위를 넓히므로 비용·확률·보상 변화도 함께 검토해야 함 |

현재 확인된 한 개 교체를 그대로 유지하며 대상 선택을 별도 조작으로 늘리지 않기 위해 **1안**을 권장한다. 2안은 사용자가 추가로 선택하면 여러 줄 교체로 범위를 변경하는 제안이다.

이번 질문은 잠금 해제와 교체 범위의 연동까지다. 기본 잠금 상태·전체 잠금 시 처리·비용·횟수·새 결과 적용·보상·지속 범위는 이후 따로 확인한다.

## 후속 확인 범위

- 변화의 단위와 지속 범위: 한 전투·단계·던전 또는 다른 범위, 파밍 실패 후 재시도의 허용 여부와 변화 유지·변경 가능 여부.
- 재화: 종류·공급·소모량·소모 시점, 재도전 시 재소모와 실패·취소 시 환급.
- 패널티: 종류·수치·개수·중첩·확률, 삭제·취소·새 결과 적용·같은 종류 재등장과 빌드가 감당하기 어려운 조합의 처리.
- 보상: 수량·품질·특정 재료 등의 강화 대상, 지급 조건과 실패 보상, 반복 수령 조건.
- 안내: 패널티와 보상의 공개 범위, 현재 빌드가 받는 영향의 설명.
- 경쟁과의 연결: 모딩 미적용과 공통 도전 조건을 유지하며 기록 인정·동률·다른 성장 요소와 비교 조건 확인.

보상 강화는 이미 획득한 희귀 장비의 성급을 바꾸거나 성급별 옵션 등급 허용 범위를 무시하는 승인이 아니다. 장비 제작의 접두·접미 3개씩, 통제 재료, 별도 실패 판정 없음 등의 규칙을 던전 변화에 자동 적용하지 않는다.

## 검증 계획

잠금 해제와 교체 대상의 연동 방식을 확인한 뒤 기본 상태·전체 잠금 처리·비용·새 결과 적용·보상·지속 범위를 제안한다. 규칙과 수치를 확인받으면 서로 다른 빌드의 패널티 대응, 성공률과 시간당 제작 재료 획득, 반복 설정 부담을 검증한다. 최고 단계 경쟁에는 모딩이 적용되지 않고 공통 도전 조건을 유지하는지도 확인한다.

현재는 도입 방향·파밍 적용 범위·무작위 부여·한 개 교체·줄 우측 잠금 토글의 조작 기획을 기록하고 미승인 연동 방식을 비교했다. 던전 변화 기능·수치·화면을 구현하거나 경제·재미 검증을 수행하지 않았다.
