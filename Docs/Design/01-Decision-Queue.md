# 사용자와 확인할 기획 순서

확인된 출발점은 [현재 방향](00-Concept.md)에 모았다. 아래 순서는 질문을 정리하기 위한 작업 순서이며 각 항목의 답은 미정이다. 사용자가 다른 주제를 먼저 다루길 원하면 순서를 바꾼다.

| 순서 | 논의할 내용 | 확인 후 구체화할 수 있는 내용 |
| --- | --- | --- |
| 1 | 한 번 접속했을 때의 플레이 흐름과 핵심 재미 | 전투 관찰, 조합 변경, 도전 선택의 연결 |
| 2 | 모바일 화면 방향과 전투 시점 | 전투에서 읽어야 할 정보와 장비·스킬 비교 공간 |
| 3 | 장비와 스킬의 관계 | 빌드가 바뀌는 원리와 조합의 선택 비용 |
| 4 | 전투 진행과 승리·실패·재도전 | 자동 전투의 판단 규칙과 결과 피드백 |
| 5 | 성장, 획득과 반복 플레이 | 파밍 목적과 보상의 순환 |
| 6 | 오프라인 진행과 복귀 경험 | 비접속 중 계산 범위와 접속 시 선택 |
| 7 | 세계관과 아트 방향 | 캐릭터, 적, 배경과 효과의 표현 기준 |
| 8 | 첫 프로토타입 범위와 검증 목표 | 구현할 최소 기능과 플레이 평가 방법 |
| 9 | 데이터 규격과 수치 | 승인된 규칙을 표현할 항목과 실험 입력값 |

과금과 운영 방식은 별도 질문으로 확인한다. 목표 이용자, 개발 인원과 일정도 정해지는 시점에 범위 논의에 반영한다. 임의의 목표 수치나 출시 일정을 채워 넣지 않는다.

## 다음 제안을 만들 때

선택지는 실제 플레이 경험의 차이가 드러나게 설명한다. 예를 들어 화면 방향을 질문할 때는 한 손 이용 가능성과 전투·장비 비교 공간을 함께 설명하고, 최종 배치와 버튼 규격은 방향을 확인한 뒤 제안한다. 서로 독립된 질문의 답을 하나의 승인으로 묶지 않는다.
