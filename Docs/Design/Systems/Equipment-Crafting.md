# 희귀 장비 기본 제작 기획

상태: 사용자에게 확인받은 현행 제작 원칙과 [DEC-0098](../Decisions/DEC-0098-crafting-execution-costs-odds-and-recovery.md)의 실행·비용·확률·종료 처리를 통합했다. 후속 [DEC-0100](../Decisions/DEC-0100-equipment-inventory-comparison-and-salvage.md)의 [장비 관리 기획서](Equipment-Inventory-Comparison-and-Salvage.md)에서 보관·비교·교체·분해를 확인했다. [DEC-0102](../Decisions/DEC-0102-initial-crafting-scope-without-extra-special-crafting.md)에서 첫 제작은 기본 4종과 집중석부터 검증하는 A안으로 확인했다. 고유 공통 규칙은 [DEC-0104](../Decisions/DEC-0104-unique-equipment-with-multiple-equipped-items.md)에서 복수 착용으로 확인했다. 첫 고유 3종의 효과·수치·중복과 빌드 검증 목표는 [DEC-0105](../Decisions/DEC-0105-first-unique-effects-stacking-and-build-goals.md)에서 확인했고 [고유 기획서](Unique-Equipment-Role-Acquisition-and-Handling.md)에 통합했다. 후속 정식 스킬·성장과 콘텐츠는 [기획 순서](../01-Decision-Queue.md)에서 확인한다.

## 목적·대상과 장비 구조

좋은 드롭 장비의 기반과 기존 옵션을 보고 제작 출발점을 고른 뒤 빌드에 맞는 조합·단계·수치를 완성한다. 희귀 장비가 추가 옵션 제작의 중심이며 고유 장비는 정해진 특수 효과를 제공하고 기본 4종 제작·집중석에서는 제외한다. 고유 복수 착용·획득·분해는 후속 [고유 공통 기획서](Unique-Equipment-Role-Acquisition-and-Handling.md)를 따른다.

희귀 장비의 추가 옵션은 접두 최대 3개·접미 최대 3개, 합계 최대 6개다. 같은 종류는 장비당 1개이며 단계·값이 달라도 같은 종류로 본다. 기반 고정 특성은 6칸과 별개이며 기본 4종 제작으로 변경하지 않는다. 획득한 성급은 고정이고 장비 간 추가 옵션 이전은 없다.

기반 목록과 특성의 역할은 [장비 구성](Equipment-Catalog-and-Base-Structure.md), 실제 기본 성능·특성 수치와 34종 후보·7단계 범위는 [장비 옵션·전투 데이터](Equipment-Affixes-and-Combat-Numbers.md)를 따른다.

## 첫 제작 검증 범위

[DEC-0102](../Decisions/DEC-0102-initial-crafting-scope-without-extra-special-crafting.md)에서 A안, 기본 제작부터 검증하는 범위를 확인했다. 기본 4종과 집중석의 그룹 통제를 첫 모델로 두고, 추가 특수 제작은 목표 빌드·파밍 시간을 정한 뒤 필요성을 다시 검토한다. 이 범위를 향후 모든 버전의 영구 금지나 이미 검증된 경제/재미로 해석하지 않는다.

| 항목 | 확정 규칙 |
| --- | --- |
| 첫 제작 구성 | 추가·제거·교체·전체 수치 재추첨과 접두/접미 통제까지. 재료는 기존 부여석·제거석·교체석·조율석·집중석 5종 |
| 특정 옵션 보호 | 개별 줄 잠금·영구 고정·접두/접미 전체 보존·특정 옵션 확정 부여는 첫 범위에서 제외 |
| 결과 복구 | 제작 결과 선택·되돌리기·보험·투자 재료 환급 없이 기존 즉시 적용 규칙 유지 |
| 아이템 자체 위험 | 파괴·성급 하락·영구 제작 불가·타락과 같은 추가 위험 제작은 도입하지 않음 |
| 수치·자리 상한 | 기존 성급별 허용 3단계와 7단계 수치 범위·접두 3+접미 3 유지. 초과 수치·일곱 번째 옵션·기반/고정 특성 변경을 주는 별도 제작 없음 |
| 종결 이후 | ‘완성 확정’ 비용·봉인·강제 제작 종료 상태를 두지 않으며 사용자가 멈추거나 계속 제작 가능. 별도 완성 보너스 없음 |
| 보호 표시 | 승인된 ‘분해 보호’는 분해만 차단하며 제거·교체·조율로부터 옵션을 보호하지 않음. 집중석도 그룹 내 특정 줄을 보호하지 않음 |
| 변경 판단 | 목표 빌드와 파밍 시간을 정한 뒤 기본 제작의 완성 비용·중간 결과 손실·최악에 가까운 연속 시도를 평가하고 특수 제작 필요성 재검토 |

분해 보호한 장비도 교체석으로 좋은 옵션을 잃을 수 있고 조율석은 모든 기존 옵션 값을 바꾼다. 접미 지정 교체는 해당 실행에서 접미만 바꾸지만 접두를 영구 고정하는 상태를 만들지는 않는다. 장비 자체의 파괴와 추가 옵션을 잃는 위험을 구분한다.

초기 범위에는 새 특수 제작 재료·효과를 등록하지 않는다. B/C의 보호·되돌릴 수 없는 강화와 후속 자동/일괄 제작·재료 교환·판매/과금·고유 제작의 개별 규칙은 이번 승인으로 확정하지 않는다. 추가할 때 기존 조율·중복·그룹·단계와 공급/비용의 변경을 기능 단위로 먼저 제안하고 확인받는다.

## 기본 작업 4종

| 작업 | 확인된 효과 | 접두/접미 통제 |
| --- | --- | --- |
| 추가 | 빈 자리에 추가 옵션 1개 생성 | 선택한 그룹에 1개 추가 |
| 제거 | 기존 추가 옵션 1개 제거 | 선택한 그룹의 기존 옵션 중 1개 제거 |
| 교체 | 기존 추가 옵션 1개 제거 후 새 옵션 1개 생성 | 제거·새 생성 모두 선택한 같은 그룹 |
| 수치 재추첨 | 현재 모든 추가 옵션의 종류·단계를 유지하고 해당 범위에서 수치만 재추첨 | 그룹 지정 대상에 포함하지 않은 별도 전체 수치 작업 |

추가·제거·교체는 필요한 실행 조건과 비용을 만족하면 별도의 성공/실패 판정 없이 작업한다. 원하는 옵션 보장과는 다르며 좋은 옵션을 잃거나 새 결과가 나빠질 수 있다. 유효 대상과 정확한 추첨·비용은 아래 제작 실행 규칙을 따른다.

수치 재추첨은 현재 붙은 모든 추가 옵션을 함께 대상으로 하며 종류·단계는 유지한다. 새 수치는 나빠져도 바로 적용하고 기존 값과 새 값 중 고르지 않는다. 각 옵션 값은 현재 단계의 정수 범위에서 독립 균등 재추첨하며 실행 조건과 비용은 아래와 같다.

## 교체·중복·단계

통제 없이 교체해도 방금 제거한 옵션과 같은 접두/접미 그룹에서 새 옵션을 생성한다. 접두·접미의 개수는 각각 유지된다. 나머지 옵션과 같은 종류를 동시에 중복시키지 않는다.

방금 제거한 종류는 새 후보에 다시 포함하므로 같은 종류가 재등장할 수 있다. 통제 여부나 같은 종류 재등장 여부와 관계없이 새 옵션의 단계는 장비 성급의 허용 범위에서 다시 추첨하며 기존보다 높거나 낮거나 같을 수 있다.

성급별 허용 단계는 1성 1~3·2성 2~4·3성 3~5·4성 4~6·5성 5~7이다. 단계별 정수 수치 범위는 [공통 데이터](Equipment-Affixes-and-Combat-Numbers.md)다. 공통 범위를 쓰는 것과 작업별 대상 추첨은 구분한다. 제작의 단계·정수값은 아래처럼 균등 추첨하며 제거/교체 대상은 기존 옵션에 대한 확률을 따른다.

## 제작 실행 확정 규칙

| 항목 | 확정 규칙 |
| --- | --- |
| 작업 비용 | 추가·제거·교체·수치 재추첨마다 해당 기본 재료 1개 |
| 그룹 통제 | 추가·제거·교체에서 접두/접미 지정 시 공통 통제 재료 1개 추가 |
| 다른 비용 | 기본 제작에는 별도 골드·대기 시간·성급별 비용 증가·반복 할증 없음 |
| 제작 장소·대상 | 전투 사이 로비/준비에서 소유한 희귀 장비 제작, 장착 중 장비도 허용 |
| 추가 | 유효 접두/접미 그룹을 균등 선택하고 그룹 안 유효 종류를 균등 추첨 |
| 제거·교체 대상 | 무통제는 붙어 있는 전체 옵션 중 균등, 통제는 선택 그룹의 기존 옵션 중 균등 |
| 교체의 새 옵션 | 제거한 그룹의 유효 종류 중 균등. 제거한 종류도 재등장 가능 |
| 단계·값 | 새 옵션의 성급별 허용 3단계는 각각 1/3, 해당 단계의 정수값은 균등 |
| 수치 재추첨 | 현재 옵션 전부의 종류·단계 유지, 각 정수값을 독립 균등 재추첨 |
| 무효 작업 | 실행 비활성·사유 안내·차감 없음. 통제로 범위를 좁힐 필요가 없으면 집중 재료 사용 비활성 |
| 확정 결과 | 실행 확정과 차감·결과 적용을 함께 처리. 같거나 나빠진 결과도 적용, 되돌리기·환급 없음 |
| 취소·중단 | 실행 전 취소는 비용 없음. 확정 뒤 종료·재접속은 같은 결과와 차감 복원, 재추첨·중복 소모 없음 |
| 장착 중 제작 | 장비 능력치 즉시 재계산. 요구 조건 미달 젬은 연결을 유지하고 사용 비활성, 조건 회복 시 재활성 |

이 표와 아래 상세 조건을 한 묶음으로 확인했다. 기존 장비당 횟수 제한 없음·기본 세 작업의 별도 성공/실패 판정 없음은 유지한다.

## 재료 이름·비용과 공급 연결

| 재료 이름 | 역할 | 한 번의 장비 제작 비용 | 기존 파밍의 각 재료 추첨 확률 |
| --- | --- | --- | --- |
| 부여석 | 옵션 1개 추가 | 1개 | 30% |
| 제거석 | 옵션 1개 제거 | 1개 | 15% |
| 교체석 | 옵션 1개 제거 후 같은 그룹에 1개 추가 | 1개 | 35% |
| 조율석 | 붙어 있는 모든 옵션의 수치 재추첨 | 1개 | 15% |
| 집중석 | 추가·제거·교체의 접두 또는 접미 지정 | 기본 비용 외 1개 | 5% |

재료 이름은 DEC-0098에서 확인한 자체 이름이다. 공급 비율은 이미 승인된 [파밍 수급](Farming-Dungeon-Modification.md)을 그대로 표시했으며 새 확률로 바꾸지 않는다.

접두 지정 교체의 비용은 교체석 1개+집중석 1개, 무통제 교체는 교체석 1개다. 1~5성과 반복 횟수에 관계없이 같은 비용이다. 조율석은 전체 옵션 수치 재추첨용이며 그룹 지정에 집중석을 쓰지 않는다.

부여석은 기존 던전 최초 패널티 1~2개 부여, 교체석은 최초 3~4개 부여와 한 줄 교체에 공유한다. 던전에서는 기존대로 해당 재료 1개를 소모한다. 집중석은 이번 기본 장비 제작의 그룹 통제 재료이며 던전 모딩에 새 통제를 추가하지 않는다.

제작 후 남은 희귀 장비의 분해 수급은 후속 [장비 관리 기획서](Equipment-Inventory-Comparison-and-Salvage.md)를 따른다. 미장착·보호 해제된 희귀 장비와 고유 단건 분해마다 기존 5종 중 재료 1개를 30/15/35/15/5%로 추첨하며 과거 제작 재료의 추가 환급은 없다. 분해 보호는 제작으로부터 옵션을 보호하는 기능이 아니며 보호 장비도 제작할 수 있다. 교환·판매·과금 공급이나 재료의 별도 등급은 별도 확인한다.

## 대상·공통 보존과 실행 조건

제작은 소유한 희귀 장비에 허용하고 고유 장비·일반/마법 장비의 승급은 이 4종 작업에서는 다루지 않는다. 장착 중인 장비와 인벤토리 장비 모두 대상이며 자동 전투가 진행 중일 때는 실행하지 못한다. 실제 로비/준비 진입과 제작 튜토리얼 해금은 별도 진행 기획에서 확인한다.

기본 네 작업은 장비의 기반·성급·희귀도·고정 특성을 보존한다. 추가/제거는 추가 옵션 개수만 1개 바꾸고, 교체와 조율은 개수를 유지한다. 제거를 반복해 추가 옵션이 0개가 되어도 희귀 장비를 유지하며 부여석으로 다시 채울 수 있다. 장비 파괴나 성급 강등 판정은 넣지 않는다.

| 작업 | 실행 가능한 상태 | 실행 불가의 예 |
| --- | --- | --- |
| 추가 | 전체 6개 미만이며 유효 그룹의 빈 칸과 아직 없는 종류 후보 존재 | 6개가 모두 참, 지정 그룹 3개가 참, 후보 없음 |
| 제거 | 대상 범위에 기존 옵션 1개 이상 | 전체 옵션 0개, 지정 그룹에 옵션 없음 |
| 교체 | 대상 기존 옵션과 같은 그룹에서 생성 가능한 새 후보 존재 | 전체 옵션 0개, 지정 그룹에 대상 없음, 후보 데이터 무효 |
| 조율 | 기존 옵션 1개 이상이며 각 옵션의 단계별 정수 범위가 유효 | 옵션 0개, 정의되지 않은 단계/범위 |
| 공통 | 필요한 기본/집중 재료 충족, 유효한 소유 희귀 장비, 전투 밖 | 재료 부족·대상 미선택·대상 상태 변경·전투 중 |

동작 직전에 최신 장비·재료·통제 조건으로 실행 가능 여부를 확인한다. 유효 후보 없는 작업은 추첨해 놓고 재료를 돌려주는 방식 대신 실행 자체를 막는다. 잘못된 후보·범위를 임의 옵션이나 범위 밖 값으로 대체하지 않는다.

## 통제 선택과 비용

기본 선택은 무통제다. 추가·제거·교체에서 접두·접미 중 하나를 지정하면 그 범위 안의 무작위 결과를 얻으며 특정 옵션 줄을 직접 지정하지 않는다. 교체는 기존 승인대로 제거와 새 옵션 생성 모두 같은 그룹이다.

무통제로도 유효 그룹이 하나뿐이면 집중석으로 좁힐 범위가 없으므로 통제 사용을 비활성화하고 기본 재료 1개로 실행한다. 예를 들어 접두 2개·접미 3개인 장비의 추가는 접두에만 가능하므로 부여석 1개면 된다. 이때 접두를 확정하려고 집중석을 추가 소모하지 않는다.

같은 장비·같은 작업에서 선택한 통제는 다음 실행에도 유지하되, 결과로 조건이 바뀌어 통제가 무의미하거나 불가능해지면 무통제로 돌아가고 이유를 안내한다. 다른 장비나 다른 작업을 선택하면 무통제로 초기화한다. 통제 없이 쓸 때 집중석을 자동 차감하지 않는다.

## 작업별 추첨

### 추가

무통제에서는 접두·접미 중 빈 칸과 후보가 있는 그룹을 같은 확률로 고른다. 둘 다 가능하면 각각 50%, 하나만 가능하면 해당 그룹 100%다. 통제하면 지정 그룹만 고른다.

그룹 안에서 이미 붙은 종류를 제외한 유효 종류를 균등 추첨한다. 이후 장비 성급의 허용 3단계 중 하나를 각각 1/3로 고르고 그 단계의 정수값을 양 끝 포함 1단위로 균등 추첨한다. 초기 34종에 모든 7단계가 정의된 데이터와 현재 성급의 허용 범위를 따른다.

### 제거

무통제에서는 붙어 있는 전체 추가 옵션 각각을 같은 확률로 고른다. 접두/접미 그룹을 먼저 50%씩 고르는 방식과 다르다. 예를 들어 접두 2개·접미 3개면 개별 옵션은 각각 20%이며, 제거될 그룹의 합계 확률은 접두 40%·접미 60%다.

통제하면 지정 그룹 안의 기존 옵션 각각을 같은 확률로 고른다. 접두가 2개인 상태에서 접두 지정 제거면 각각 50%다. 선택하지 않은 다른 옵션은 그대로 보존한다.

### 교체

제거 대상은 위 제거와 같은 확률로 고른다. 선택한 기존 옵션을 후보 계산에서 뺀 상태로, 같은 접두/접미 그룹의 유효 종류를 균등 추첨한다. 방금 제거한 종류도 포함하고 나머지 옵션과 같은 종류는 제외한다.

새 옵션의 단계와 값은 추가와 같은 방식으로 각각 균등 추첨한다. 같은 종류가 다시 나와도 단계·값을 다시 뽑으며 기존보다 낮거나 같은 결과도 허용한다. 접두/접미 개수와 나머지 옵션의 종류·단계·값은 보존한다.

### 조율

현재 붙어 있는 모든 추가 옵션의 종류·단계는 유지하고 각 옵션의 정수값만 독립 균등 추첨한다. 옵션마다 현재 단계의 범위를 사용한다. 장비 전체를 하나의 공통 확률값으로 함께 올리거나 내리는 방식은 쓰지 않는다.

기존 값·최댓값도 추첨 후보에 포함한다. 전체 결과가 같거나 일부/전부 나빠져도 새 값을 바로 적용하고 조율석을 정상 소모한다. 하나의 수치만 지정해 조율하거나 새 값과 옛 값 중 고르는 기능은 제공하지 않는 기존 원칙을 유지한다.

## 정보·확정·취소와 재접속

실행 전에 대상 장비·작업·통제 여부와 총 재료 비용, 바뀔 범위와 잃을 수 있는 옵션, 제거 대상 확률·새 종류/단계/값의 조건부 확률을 게임 안에서 확인하게 한다. 조율은 기존 종류·단계가 유지되고 전체 수치가 바뀐다는 점을 보여 준다. 실제 화면 배치·버튼·연출 시안은 후속 UI에서 다룬다.

실행 확정과 재료 차감·결과 적용은 한 번의 작업으로 함께 처리한다. 결과를 미리 확인하고 소모를 취소하는 선택지는 두지 않는다. 실행 전 취소·화면 닫기·장비/작업 변경은 차감하지 않고, 확정한 결과는 좋고 나쁨과 무관하게 되돌리기·환급하지 않는다.

실행 확정 전에 앱을 닫으면 소모 없이 기존 상태를 유지한다. 확정 뒤 앱 종료·접속 중단은 같은 결과와 차감을 보관하고 복귀 때 복원한다. 같은 실행의 재추첨·중복 소모·옵션 이중 적용을 허용하지 않는다. 구현의 저장 방식과 서비스 구조는 별도 기술 조사에서 정한다.

장착 중 장비의 결과는 전투 능력치에 즉시 반영한다. 젬 요구 조건에 미달하면 장착/연결 위치는 보존하고 해당 젬의 사용을 비활성화하며 미달 능력치를 안내한다. 다시 조건을 만족하면 재활성화한다. 이 처리로 젬 아이템을 버리거나 새로 얻도록 만들지 않는다. 전체 스킬 세트의 자동 사용 순서·진행 제한은 별도 스킬/진행 기획에서 확인한다.

## 판단 예시

접두 2개·접미 3개 장비에 추가하면 접두 1개를 넣을 수 있다. 원치 않는 접미를 바꾸려면 교체석만 써 전체 5개 중 하나를 교체하거나, 교체석+집중석을 써 접미 3개 중 하나를 교체한다. 집중석이 특정 좋은 접미를 보호하거나 원하는 접미 하나를 보장하는 재료는 아니다.

예를 들어 한손검의 접두 후보 6종 중 2종이 붙어 있으면 추가할 접두 종류는 4종, 각 1/4이다. 5성 장비는 옵션 5·6·7단계를 각각 1/3로 뽑는다. 조율은 그 종류·단계를 고정하고 여러 수치만 다시 노리는 작업이다.

이 사례는 규칙의 조건부 확률 설명이며 원하는 완제품까지의 평균 비용이나 성공 보장으로 취급하지 않는다. 좋은 중간 결과를 사용할지, 잃을 위험을 감수하고 계속 제작할지의 판단을 남긴다.

## 횟수·후속 확인과 검증

기본 4종에는 장비당 제작 횟수 제한이 없다. 실행 조건과 비용을 만족하면 같은 장비를 계속 다듬을 수 있으며 반복 횟수로 제작 가능 횟수가 소진되거나 비용이 증가하지 않는다.

제작의 이름·비용·추첨과 실행/종료는 [DEC-0098](../Decisions/DEC-0098-crafting-execution-costs-odds-and-recovery.md)에서 확인했다. 장비 보관·비교·교체·분해와 회수는 [DEC-0100](../Decisions/DEC-0100-equipment-inventory-comparison-and-salvage.md)의 [장비 관리 기획서](Equipment-Inventory-Comparison-and-Salvage.md)를 따른다. [DEC-0102](../Decisions/DEC-0102-initial-crafting-scope-without-extra-special-crafting.md)에서 첫 제작은 기본 4종과 집중석부터 검증하는 A안으로 확인했다. 위 ‘첫 제작 검증 범위’에 통합했다. 후속 모델의 보호/특수 제작·자동/일괄 제작·직접 옵션 지정·재료 교환/다른 공급·정식 스킬/성장은 다시 제안하고 확인받는다. 고유 공통 규칙은 [DEC-0104](../Decisions/DEC-0104-unique-equipment-with-multiple-equipped-items.md)에서 복수 착용으로 확인했다. 첫 고유 3종의 효과·수치·중복과 빌드 검증 목표는 [DEC-0105](../Decisions/DEC-0105-first-unique-effects-stacking-and-build-goals.md)에서 확인했고 [고유 기획서](Unique-Equipment-Role-Acquisition-and-Handling.md)에 통합했다. 후속 정식 스킬·성장과 콘텐츠는 [기획 순서](../01-Decision-Queue.md)에서 확인한다.

[PoE 2 제작 연구](../../Research/Crafting/README.md)와 [제작 실행 조사](../../Research/2026-11-18-crafting-execution-costs-and-odds.md)에 출처·버전·라이선스·호환성과 재사용 제약을 정리했다. 비용·균등 추첨은 우리 게임의 자체 초기 규칙이며 PoE의 현행 수치를 반입한 것이 아니다.

이번 변경은 문서 반영이다. 제작·저장·UI·전투의 실제 구현과 게임 경제 검증을 수행하지 않았다. 구현 전에 기술 조사와 적용·검증 계획을 제안한다. 이후 작업별 유효/무효·통제/강제 그룹·개별 대상 확률·교체 그룹 유지/재등장·단계/값 분포·조율 독립성/보존·차감/즉시 결과·취소/중단/복원·장착 능력치와 젬 조건을 검증한다. 스킬·몬스터·파밍 시간을 정한 뒤 수급과 제작 비용을 연결해 중간/종결 완성과 긴 실패 연속의 소요 분포를 비교한다.

[특수 제작 범위 조사](../../Research/2026-11-18-crafting-preservation-and-special-scope.md)의 문헌과 실제 실행을 구분하며, 보호 토글 유무의 후보/확률 일치·그룹 밖 옵션 보존·조율의 전체 수치 변경·기반/성급/수치 상한·반복 제작 가능 상태를 후속 검증할 계획이다. 이번에는 제작 시뮬레이터·Unity 전투/저장·경제 실험을 실행하지 않았다.
